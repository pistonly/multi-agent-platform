# 实验计划：UI 评论输入 @ 应自动弹出可选 agent 名称

## 背景
话题「UI 评论输入 @ 应自动弹出可选 agent 名称」经两轮讨论已达共识：在评论输入框中输入 `@` 字符时应自动弹出可选 agent 名称的下拉列表，便于用户快速 @ 提及特定 Agent。本实验将该共识落地为代码实现并通过端到端测试验证。

## 目标
- 评论输入框输入 `@` 后弹出可选 agent 列表
- 列表按输入前缀过滤（fuzzy / prefix 匹配）
- 键盘上下方向键、回车、Esc 行为符合常见 IDE / IM 习惯
- 选中后自动补全 `@agent-name` 并把光标定位到合适位置

## 范围
- 前端评论输入组件（React / Vue，需按仓库实际栈）
- 现有 `agents` 数据源拉取（直接复用或新增 API）
- 端到端测试（Playwright / Cypress）

## 非目标
- 不实现富文本 @ 高亮渲染（仅完成下拉候选与插入）
- 不实现后端通知 / Webhook（仅前端 UI）
- 不动现有评论存储结构

## 验收标准
1. 输入 `@` 后 ≤ 300ms 内出现候选列表
2. 继续输入字符时列表实时过滤
3. 上下方向键 + 回车可选择并插入
4. Esc 关闭候选列表
5. 候选为空时显示「无匹配 agent」占位文案
6. 端到端测试覆盖上述 5 条核心交互

## 实现步骤
1. **后端**：确认 `GET /api/agents` 列表接口已存在；若不存在新增（仅返回 id、name、display_name）
2. **前端组件**：在评论输入框挂载 `@-trigger` 监听器，捕获光标位置
3. **候选弹层**：复用通用 `Popover` / `Autocomplete` 组件（若无则新建）
4. **过滤逻辑**：按 `@` 后输入子串做不区分大小写前缀匹配
5. **键盘交互**：↑↓ 导航、Enter 选择、Esc 关闭、Tab 也可关闭
6. **样式**：候选项显示 agent display_name + 弱化 id，与现有设计系统一致
7. **测试**：
   - 单元测试：过滤函数 + 键盘导航 reducer
   - E2E 测试：完整输入 → 选择 → 提交流程

## 风险
- 现有输入组件可能是受控 `<textarea>` 而非富文本编辑器，候选定位需要监听 `selectionStart`
- Agent 数量较大时需要做虚拟滚动 / 上限截断（默认显示前 50 条）
- 中文输入法（IME）组合输入期间不应触发弹层

## 回滚
本次改动收敛在前端单组件 + 后端只读接口，发布失败可单 PR revert，不影响其他流程。
