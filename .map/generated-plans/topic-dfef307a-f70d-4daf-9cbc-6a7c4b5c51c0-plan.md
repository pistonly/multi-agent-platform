# 实验计划：待办 → @ 提及跳转自动锚定到被 @ 的评论

## 背景

在 MAP Web 端的待办/通知流中，用户点击一条「@你的评论」时，当前只会跳转到话题详情页或评论列表顶部，但**不会自动滚动定位到那条被 @ 的评论**。这导致用户必须再次手动检索上下文，尤其是长话题里被引用的评论往往位于话题中部偏后，体验割裂。

本话题经两轮讨论已收敛：在 Web 前端评论列表组件中加入「目标评论 ID → 自动滚动 + 高亮」逻辑，并在 URL 上携带锚点参数以便刷新/分享仍可还原定位。

## 目标

1. 用户从待办/通知点击 @ 提及时，自动跳转并**锚定到被 @ 的那条评论**。
2. 目标评论在视口内可见（必要时滚动到位），并提供短暂的视觉高亮反馈。
3. URL 携带可分享/可刷新的锚点信息（如 `#comment-<uuid>`）。

## 范围

### In Scope
- Web 前端：评论列表组件接收目标 `comment_id`，定位并滚动到该评论。
- Web 前端：路由层解析 URL 锚点参数（`?anchor=<comment_id>` 或 `#comment-<uuid>`），传入列表组件。
- Web 前端：目标评论加载完成前的**等待/重试**逻辑（评论懒加载或分页场景）。
- 待办/通知入口：跳转到话题详情页时附带 anchor 参数。
- 短暂的视觉高亮（如淡黄背景 1.5s 后渐隐）。
- 自动化测试：滚动/锚定行为的单元/集成测试覆盖（包含加载前/加载后两种时序）。

### Out of Scope
- 桌面/移动客户端（本期仅 Web）。
- 评论嵌套回复中的二级 @ 提及（仅顶层 @ 跳转）。
- 邮件/IM 通知渠道的同款跳转（本实验不覆盖）。

## 验收标准（Acceptance Criteria）

1. **AC-1**：在话题详情页 URL 后追加 `?anchor=<comment_id>` 访问，页面加载完成后该评论**位于视口内**，且**无额外用户滚动**。
2. **AC-2**：从待办列表点击一条 @ 提及，落地页跳转后**目标评论位于视口内**，并出现**≥1s 的视觉高亮**。
3. **AC-3**：若目标评论尚未加载（如分页未拉取），前端会**自动加载/翻页**直到目标评论出现，再执行滚动（最多等待 N 秒，超时回退到顶部并提示）。
4. **AC-4**：复制落地页 URL 在新标签打开，仍能正确定位（刷新/分享不丢失锚点）。
5. **AC-5**：自动化测试覆盖至少 2 个场景：(a) 直接打开带锚点 URL；(b) 点击 @ 后跳转到带锚点 URL。
6. **AC-6**：当 anchor 指向不存在的 comment_id 时，前端**优雅降级**（不抛白屏、不循环重试），并在控制台留下可观测日志。

## 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 评论懒加载未到达目标评论 | 滚动不到位 | 监听列表渲染完成事件 + 设置最大等待/重试次数，超时降级 |
| 评论组件被虚拟滚动/分页包裹 | DOM 未挂载 | 与列表组件 owner 协作，确认虚拟滚动 API（如 react-virtuoso 的 `scrollToIndex`）支持 |
| 锚点参数被中间件/代理剥离 | 分享/刷新失效 | 路由层显式保留 query/hash；E2E 测试覆盖 |
| 视觉高亮干扰阅读 | 体验下降 | 高亮时长 ≤ 2s，可被用户点击/滚动提前消除 |

## 实现要点（指引，非设计锁定）

1. 在话题详情页路由组件解析 `anchor`（或 hash 中的 comment id），下发给 `CommentList`。
2. `CommentList` 维护「目标评论」prop，渲染完成后调用 `scrollIntoView({ behavior: 'smooth', block: 'center' })`，并临时添加高亮 class。
3. 若目标评论未在当前渲染集合内，触发**加载更多/翻页**直到命中；命中前保持 loading 状态。
4. URL 持久化：保留 query/hash 参数，便于刷新与外链分享。
5. 监控：在落地跳转路径埋点，记录「anchor 命中 / 未命中 / 超时」三类比例。

## 里程碑

- **M1（设计/接口对齐）**：与 CommentList owner 对齐 anchor 下传协议；敲定高亮样式与时长。
- **M2（前端实现）**：完成路由解析、列表定位、加载等待逻辑；本地通过自测。
- **M3（自动化测试）**：补齐 AC-5 要求的单测/E2E。
- **M4（灰度上线）**：内部环境验证 → 生产灰度 → 全量。
