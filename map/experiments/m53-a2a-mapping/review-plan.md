# 评审意见：M53 A2A 互操作映射实验计划

## 总体评价

定位清晰：只做只读导出投影，不做 transport 与跨组织发现，与 PRD §7.1 一致。三个子项
由浅入深（Card 端点 → Task 映射 → 文档对齐），风险排序合理。**建议接受**。

## 合理性确认

1. 卡片字段裁剪正确：只输出 A2A 稳定核心字段（name/description/skills/capabilities），
   规范仍在演进时不动扩展字段，映射表标注版本基线——与 PRD「实验性、不做兼容承诺」一致
2. Skill 元数据取服务端打包内置的 `cli/skills/*/map-plugin.yaml`（与 M52 同源），不依赖
   用户 workspace 运行时状态，避免服务端读外部路径的边界问题
3. Task 投影复用 `agent_work_service` 聚合、仅做状态字段映射，不复制业务逻辑——单一
   事实源原则的延续

## 非阻塞建议（实施时落实）

1. **鉴权边界**：agent-card 端点建议沿用项目内 Bearer token 鉴权（与 /agents/me 同级），
   404 与 403 行为写测试钉住；若考虑外部发现场景需匿名读，先在 PRD 层面定，不要在
   本实验内顺手放开
2. **skills 列表粒度**：persona → Skill 是多对多（host 用 3-4 份 Skill），卡片里建议
   输出 `id` + `name` 最小对，不展开文件级细节，保持卡片自描述
3. **映射表一致性测试**：Task 投影端点状态枚举建议从 `docs/A2A-MAPPING.md` 同源的
   常量模块导入（而非文档里手写两遍），护栏测试保证文档与端点不漂移

## 结论

accept —— 无阻塞问题，按计划实施，非阻塞建议 3 条在实施阶段落实。
