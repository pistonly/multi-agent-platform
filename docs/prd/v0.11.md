## 1. 变更摘要

v0.10 及之前的版本重心在协作对象建设与自动推进（实验状态机、通知降噪、waker、direct 模式）。评审结论是：协议层已经达标（wake 协议、错误信封、`map work` 快照），当前失分集中在**接入链路、事实源分裂和文档漂移**。v0.11 是一个「偿债 + 借力」版本：四个杠杆点全部来自现有代码与文档证据，不引入新协作对象。

| 领域 | 现状 | v0.11 目标 |
|------|------|------|
| 话题事实源 | FS / DB 双轨，Agent 每次操作前先判别 | `map topic` 统一入口自动路由；`map fs` 降为高级命令 |
| 文档一致性 | 路径、端口、现行版本指向多处漂移 | 单一真相源 + docs 一致性 pytest 护栏 |
| Skill 分发 | 无版本、默认绑定 Cursor 路径、装后无校验 | 版本清单、多 runtime 目标、升级 diff、装后自检 |
| 接入凭据 | bootstrap token 丢失后不可恢复 | `map auth reissue` 重签发 |
| 生态互操作 | 私有 API / CLI（`map-mcp` 面向外部项目保留） | persona 导出 A2A Agent Card、Task 语义映射表 |

### 设计约束

- M50 全部为文档与小工具改动，可独立先行合入，不阻塞 M51-M53
- M51 不删除 `map fs` 命令族，只改变推荐入口，保持向后兼容
- M53 为实验性里程碑，只做「导出投影」，不实现 A2A transport 网关
- v0.10 direct 模式与 standard 模式行为不受任何里程碑影响

## 2. 背景与动机

### 2.1 评审结论摘要

以「Agent 方便程度」和「应用价值」两轴评审，结论分三类：

1. **已达标的**：错误即恢复指令（`recovery_command` + escalation 自动定位）、`map work` 统一快照 + 51 行 wake 协议、渐进披露的 Skill 分层、CLI surface 快照测试（`tests/cli/test_compat.py`）。
2. **拖后腿的**：FS/DB 双轨带来每次操作的判别税；QUICKSTART 首条示例命令参数错误；端口与现行版本指向多处不一致；`map skill install` 无升级机制。
3. **窗口期风险**：A2A 协议已进入 Linux Foundation 并获 150+ 组织采用，MAP 的 persona / topic / experiment 概念与其 Agent Card / Task 天然同构，但当前没有任何映射出口。

### 2.3 外部动因

A2A 协议在首个周年时由 Linux Foundation 接管治理，超过 150 家组织参与，并已在三大云平台进入生产使用（来源：[Linux Foundation 公告](https://www.linuxfoundation.org/press/a2a-protocol-surpasses-150-organizations-lands-in-major-cloud-platforms-and-sees-enterprise-production-use-in-first-year)、[a2a-protocol.org](https://a2a-protocol.org/dev/)）。业界正在形成「MCP 连工具、A2A 连 Agent」的双协议栈。MAP 已经在 MCP 一侧有 `map-mcp`（面向外部项目保留），A2A 一侧完全空白。对 MAP 而言，persona 即 Agent Card、话题轮次与实验生命周期即 Task 状态，映射成本低于多数同类产品；先做导出投影，是对冲标准风险成本最低的一步。

## 3. 设计原则

### 3.1 单一事实源

同一条规则只在一处定义：行为规则以 Skill 为准（AGENTS.md 降级为索引）、PRD 版本以 `docs/prd/README.md` 为准（INDEX 只引用不复制）、待办以 `map work` 为准。任何文档不得复制另一文档的规则表，只能链接。

### 3.2 偿债优先于新能力

v0.11 不新增协作对象、不新增状态机路径。全部四个里程碑都在收敛、修复或暴露既有能力。

### 3.3 复用优先（延续 v0.10）

M51 的路由层复用现有 `cli/commands/topic.py` 与 `fs.py` 的实现；M53 的 Agent Card 复用 persona 注册信息，不新建存储。

### 3.4 每条修复配护栏

文档类修复不允许只改文字：凡在 M50 修复的漂移类别，须同时在 `tests/test_docs_consistency.py` 中加对应断言，让 pytest 而不是评审者来防复发。

## 5. M51 话题事实源收敛（P1）

### 5.1 现状与问题

`map fs`（文件即话题）与 `map topic`（DB 话题）两套命令族并存：

- Agent 被唤醒后每次都要先判别话题类型（`map fs list` 找 slug），判错即 404；uuid5 派生 id 传入 DB 命令是文档化的红线
- 待办清理分发表因此分叉（`pending_topic_replies` 有 DB / FS 两条路径）
- 双轨专属代码约 1400 行（`cli/commands/fs.py` 830 行 + `sdk/python/map_fs/parser.py` 566 行）加专属测试
- 最近提交（`map/` 目录成为 source of truth + participant whitelist）表明方向本就是 FS 优先，双轨是过渡态

### 5.2 方案

`map topic` 成为唯一推荐入口，路由规则内建于 CLI：

1. **自动路由**：`--id <uuid>` 走 DB；`--id <slug>` 走 FS；同 slug 冲突时要求 `--storage fs|db` 显式指定
2. **服务端 FS 索引注册**：FS 话题的 uuid5 派生 id 注册进服务端话题索引（只读投影），使 `map topic show/comment --id <fs-uuid>` 同样可用，消灭 uuid5 红线
3. **`map fs` 降级**：命令族保留（纯本地写、离线场景），文档标注为 advanced；wake.md 与 commands.md 中所有「先判别再选命令」的段落删除，分发表合并为单列
4. **存量 DB 话题**：默认保留可操作；提供 `map topic migrate --id <uuid> --slug <name>` 单向迁移到 FS（DB 记录标记 migrated，列表默认隐藏）

### 5.3 影响面

| 对象 | 变化 |
|------|------|
| `wake.md` | 删除话题类型判别步骤，清理分发表从 12 行合并为 8 行左右 |
| `commands.md` | DB/FS 双列说明合并为单列 + `--storage` 覆盖说明 |
| `cli/commands/topic.py` | 增加路由层（slug/uuid 判别 + 委派），`fs.py` 主体不动 |
| 服务端 | 新增 FS 话题索引注册端点（bootstrap 时与 `map fs` 验证型写时同步） |
| ARCHITECTURE.md | 重写为 v2：三层分工图、44 迁移后的实体全景、FS 事实源、通知分层（挂靠本里程碑末尾，可拆独立 PR） |

## 6. M52 Skill 分发与接入可靠性（P1）

> **执行状态：✅ 已完成**（2026-08-15，direct 模式实验 `2f95f555-28b9-4a8f-b6c9-c13a77dbbf6d`）。M52A-D 全部落地，测试 372（快速门控）+ 16（skill_install）全绿；wire 级 reissue 待 API 进程常规重启后生效（TestClient 级轮换已验证）。日志见 `map/experiments/m52-skill-distribution/log.md`。

### 6.1 Skill 版本化

- 每个 Skill 目录新增 `map-plugin.yaml`：`version`（语义化）、`requires`（map CLI 最低版本）、`runtime_targets`（支持的安装目标列表）
- `map skill install` 写入版本清单到目标目录；已存在时不再静默 skip，而是提示当前版本与可用版本
- `map skill list --installed` 显示已装版本与内置版本的 drift
- `map skill upgrade [--force]`：先输出 diff 摘要（新增/删除/变更文件数与行数）再覆盖；`--force` 保留原整目录覆盖语义
- 装后自检：install 成功后输出下一步命令（`map persona whoami` 验证链路），失败时给出 `bootstrap-troubleshooting.md` 定位锚点

### 6.2 多 runtime 目标

`--runtime cursor|claude-code|codex|generic`，默认 `cursor`（向后兼容），映射：

| runtime | 目标目录 |
|---------|----------|
| cursor | `.cursor/skills/` |
| claude-code | `.claude/skills/` |
| codex | `.codex/skills/` |
| generic | `./skills/`（自述路径约定） |

### 6.3 bootstrap token 恢复

- 新增 `map auth reissue --name <agent-name> --key <project-key>`：凭项目 key 重签发 token，旧 token 吊销，写回 `.map/agents.local.yaml`
- bootstrap 409（agent 名已存在）时的错误信息从「无法找回」改为给出 reissue 命令
- `.map/agents.local.yaml` 首次写入时提示备份（含恢复命令）

### 6.4 QUICKSTART 重排

自动化协作路径补全：Step 6 增加 waker 启动说明（`./scripts/start-all-wakers.sh` 或外部项目等效方式），消除「外部用户想自动推进时指引断裂」。

## 7. M53 A2A 互操作映射（P2，实验性）

### 7.1 定位

只做「导出投影」：把 MAP 的既有对象映射为 A2A 概念并暴露只读端点，验证互操作可行性，为未来双向网关保留判断空间。不实现 A2A transport，不做跨组织发现。

### 7.2 M53A：Agent Card 导出

- `GET /api/v1/projects/{id}/agent-cards` 与每 agent 的 `GET /api/v1/agents/{id}/agent-card`
- 映射：`name` = agent_name（如 `multi-agent-platform-host`）、`description` = persona 职责一句话、`skills` = 该 persona 的 Skill 清单、`capabilities` 按 persona 固化（host: 主持/创建实验；participant: 评论/执行；reviewer: 评审）
- 内容复用 persona 注册信息与 Skill 元数据（M52 的 `map-plugin.yaml`），不新建存储

### 7.3 M53B：Task 语义映射表

| MAP 对象 | A2A Task 概念 | 映射规则 |
|----------|---------------|----------|
| topic round | Task | round open = `working`；advance-round = `completed`；每轮产物文件 = artifact |
| experiment lifecycle | Task state | draft = `submitted`；review/approved/running = `working`；done = `completed`；cancelled = `failed` |
| `map work` | Task 查询 | 投影为只读 Task 列表（每 persona 视角） |

映射表落在 `docs/A2A-MAPPING.md`，附 JSON 示例；端点返回的 Task 投影与映射表一致。

### 7.4 M53C：MCP 面向外部项目对齐

`docs/MCP.md` 与 QUICKSTART 对齐（端口、安装示例、与 CLI+Skill 的定位关系），明确「本仓库用 persona + CLI，外部项目可用 MCP 或 CLI 任一」。
