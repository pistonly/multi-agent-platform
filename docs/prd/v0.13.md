## 背景与动机

v0.11 确立 FS 事实源（`map/` 目录实时解析、平台只做解析器/渲染层），v0.12 完成 Agent 人机工程收口（机器可读输出、错误信封、路由统一）。但 FS 改造的双轨尾巴尚未清理：

- **fs-refactor-review 话题**（2026-08-15 close）确认的 P1/P2 行动项中，仅 `fs-participant-whitelist`（P1）已落地实验，其余四项悬置；
- **M54/M56 实验**各留一项已决策延后事项，堆积到本版本；
- **v0.12 非目标**显式让位的工程卫生项（lint 盲区）需要归属。

v0.13 的定位是**清偿版**：不新增领域能力，把「双轨并存期」的既定债务逐项收口，让 DB 话题写路径正式进入退役流程。

## 设计原则

1. **对称性**：实验计划与实验日志是同构对象，输入形态（`--file` / `--file-path`）必须对齐，瘦身门禁规则复用 M55 成果。
2. **零存量退役要证据先行**：fs-refactor-review round2 原定「deprecation warning + 1–2 个 minor 过渡期」，其前提（FS 投影不完整）已被 v0.11/v0.12 消除且存量为零；直接退役的证据链（存量 / waker 桥接 / Skill 依赖面 / 语义缺口）须在 PRD 留痕，**Skill FS 化改写是移除的硬前置门禁**。
3. **观测先于优化**：`scan_plane` 先记基线与触发条件，不预做 mtime 增量（YAGNI，participant round1 建议）。
4. **设计决策也是交付**：F6/F7 允许以「设计结论回写 PRD 风险表」形态结项，不强制实施。

## 非目标

- **不删除** topics / comments / mentions 表与历史数据（只读展示与审计依赖）；移除的仅是话题域写路径入口。
- **不动**实验状态机与通知系统的 DB 存储（DB 退役范围严格限定在话题域写路径，实验/通知仍以 DB 为准）。
- **不实现** mtime 增量扫描 / 目录监听（只记基线与触发条件，等规模信号）。
- **不默认实现** topic/agent 族短 id（除非 M59 设计评估结论为低成本且评审通过）。
- 不动 A2A 投影、实验状态机、waker 协议（维持 v0.11/v0.12 交付面）。
