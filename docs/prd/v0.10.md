# 多 Agent 实验协作平台 — 产品需求文档（PRD）

> 版本：**v0.10 草案**
> 日期：2026-08-13
> 状态：**草案**
> 基线：[status-md-v10](../status-md-v10.md)（v0.8+ waker Phase 1、inbound_event 去重、action items）
> 主题：Plan 模式 — host 直接指定计划并委派 participant 执行，跳过 reviewer 门禁

---

## 1. 变更摘要

MAP 的实验生命周期目前强制经过两个 reviewer 门禁：**review**（计划审批）和 **result_review**（结果审批）。对于 host 已经明确知道要做什么、只需要 participant 去执行的场景，这两个门禁增加了不必要的延迟和协作开销。

v0.10 引入 **`ExperimentMode.direct`**：host 创建实验时指定 `mode=direct`，状态机跳过 review 和 result_review，participant 直接接收计划并执行。

| 主题 | 现状（standard 模式） | v0.10 direct 模式 |
|------|------|------|
| 生命周期 | draft → review → approved → running → result_review → done | draft → running → done |
| reviewer 门禁 | 2 个（计划审批 + 结果审批） | 0 个 |
| 执行者 | host 或 `--executor` 委派 | `--executor` 委派（通常 participant） |
| Plan 版本管理 | PlanVersion + frontmatter 校验 | 保持不变 |
| phase_owner (running) | host | participant |
| complete 后去向 | result_review（reviewer 审批） | done（直接完成） |
| cancel 权限 | host 保留 | host 保留 |

### 设计约束

- `mode` 在创建时指定，**不可中途切换**——避免状态机混乱和审计歧义
- direct 模式仍保留 `PlanVersion` 版本管理和 frontmatter 校验
- host 保留 `cancel` 权限；executor（participant）只能 `complete`
- direct 模式的 `complete` 仍要求 evidence metadata，但降级为 warning（不阻断）
- 现有 standard 模式行为**完全不受影响**

---

## 2. 设计原则

### 2.1 复用优先

direct 模式不引入新对象类型。它复用 Experiment、PlanVersion、executor 委派、todos/waker、host invoke 等全部现有设施，只在状态机层增加一条快速路径。

### 2.2 模式不可变

`mode` 是实验的创建时属性，写入后只读。这保证：
- 状态机转换规则在整个生命周期内一致
- 审计日志可以明确还原"这个实验从一开始就是 direct 模式"
- 不需要处理"运行中切换模式"的边界情况

### 2.3 standard 模式零影响

所有现有实验的 `mode` 默认为 `standard`。状态机、phase_owner、todos、waker、Skill 在 `standard` 模式下行为完全不变。direct 模式的逻辑通过条件分支隔离，不修改现有转换规则。

## 4. 状态机

### 4.1 direct 模式转换规则

```
draft    → running, cancelled
running  → done, cancelled
done     → (终态)
cancelled → (终态)
```

对比 standard 模式：

```
draft    → review, cancelled
review   → approved, draft, cancelled
approved → running, cancelled
running  → result_review, cancelled
result_review → done, running, cancelled
done     → (终态)
cancelled → (终态)
```

### 4.2 实现

`validate_phase_transition` 增加可选 `mode` 参数：

```python
def validate_phase_transition(
    current: ExperimentPhase,
    target: ExperimentPhase,
    *,
    mode: str = "standard",
) -> None:
```

当 `mode == "direct"` 时使用 direct 转换表，否则使用现有 standard 转换表。

### 4.3 不支持的转换

direct 模式下以下操作会被 `StateMachineError` 拒绝：
- `submit_for_review`（draft → review）
- `approve_experiment`（review → approved）
- `accept_result`（result_review → done）
- `reject_result`（result_review → running）

这些操作在 direct 模式下无意义，因为对应的 phase 不存在于生命周期中。

## 5. Phase Owner 路由

direct 模式下 running 阶段的决策者是 participant（executor），而非 host：

| Phase | standard owner | direct owner |
|-------|---------------|-------------|
| draft | host | host |
| running | host | participant |
| done | host | host |
| cancelled | host | host |

`phase_owner_resolver.owner_for()` 增加可选 `mode` 参数：

```python
def owner_for(phase, *, mode="standard") -> PhaseOwner:
    if mode == "direct" and phase == ExperimentPhase.running:
        return PhaseOwner.participant
    ...
```

这影响：
- `informational_only` 分类：direct 模式下 running 阶段对 host 是 informational_only（等待 participant 执行）
- todos 投影：running 阶段的实验出现在 participant 的 todos 中
- waker：唤醒 participant 而非 host

## 6. API / SDK / CLI 需求

### 6.1 API

`POST /projects/{project_id}/experiments`（create）请求体增加：

```json
{
  "mode": "direct"
}
```

默认 `"standard"`，向后兼容。

`POST /experiments/{id}/start` 在 direct 模式下：
- 允许 `draft → running`（跳过 review/approved）
- `executor_agent_id` 必传（或默认为 actor.id）

`POST /experiments/{id}/complete` 在 direct 模式下：
- 转换 `running → done`（跳过 result_review）
- evidence metadata 校验降级为 warning

### 6.2 SDK

`ExperimentCreate` 增加 `mode: ExperimentMode = ExperimentMode.standard`。
`ExperimentSummaryRead` 增加 `mode: ExperimentMode`。
`ExperimentStart` 不变（`executor_agent_id` 已支持）。

### 6.3 CLI

```bash
# 创建 direct 模式实验
map --persona host experiment create \
    --title "实现某功能" \
    --plan-file ./plan.md \
    --mode direct \
    --topic-id <uuid>

# start（direct 模式下从 draft 直接到 running）
map --persona host experiment start --id <uuid> --executor participant

# participant 完成（direct 模式下直接 → done）
map --persona participant experiment complete \
    --id <uuid> \
    --summary "完成实现" \
    --file ./log.md

# host 取消（保留）
map --persona host experiment cancel --id <uuid>
```

`experiment create` 增加 `--mode` 选项（默认 `standard`）。
`experiment list` 输出增加 mode 列。

## 7. Service 层变更

### 7.1 create_experiment

`project_service.create_experiment` 接受 `payload.mode`，写入 `experiment.mode` 字段。direct 模式下 `submit_for_review=True` 被忽略（没有 review 阶段）。

### 7.2 start_experiment

`phase_service.start_experiment` 在 direct 模式下：
- 调用 `validate_phase_transition(current, running, mode=experiment.mode)`
- 允许从 `draft` 直接跳到 `running`
- `executor_agent_id` 逻辑不变

### 7.3 complete_experiment

`phase_service.complete_experiment` 在 direct 模式下：
- 调用 `validate_phase_transition(current, done, mode=experiment.mode)`
- 允许从 `running` 直接跳到 `done`
- evidence metadata 校验：direct 模式下缺失时记 warning log，不 raise
- 跳过 `accept_result` 的 reviewer 审批流程
- 触发 A2 action_item cascade（与 standard 模式一致）

### 7.4 不支持的操作

`submit_for_review`、`approve_experiment`、`accept_result`、`reject_result` 在 direct 模式下调用时，`validate_phase_transition` 会自然拒绝（因为目标 phase 不在 direct 转换表中）。错误信息应包含 mode 提示。

---

## 8. Todos / Waker 适配

### 8.1 todos 投影

direct 模式实验在 `running` 阶段：
- 出现在 **executor（participant）** 的 `my_executing_experiments` todos 中
- 对 host 标记为 `informational_only`（等待 participant 完成）
- host 的 todos 中不出现 actionable 项

### 8.2 waker

simple-waker 轮询 `map work` 时：
- participant 的 work items 包含 direct 模式 running 实验
- host 的 work items 中 direct 模式 running 实验标记为 informational_only

---

## 9. 非目标

v0.10 不做：
- 运行中切换 mode
- direct 模式的 reviewer 可选介入（如果需要 reviewer，用 standard 模式）
- direct 模式实验的计划 diff 对比（PlanVersion 仍可 revise，但没有 review 阶段）
- 独立的 Plan 对象类型（方案 B，留待未来评估）
- Web UI 的 mode 切换控件

## 10. 验收标准

### M40A：数据模型

- `experiments.mode` 字段存在，默认 `standard`
- 旧实验数据自动获得 `standard` 值
- `ExperimentMode` enum 在 `map_types/enums.py` 中定义
- SDK `ExperimentCreate` / `ExperimentSummaryRead` 包含 `mode` 字段

### M40B：状态机

- direct 模式下 `draft → running` 转换成功
- direct 模式下 `running → done` 转换成功
- direct 模式下 `draft → review` 转换被拒绝
- direct 模式下 `running → result_review` 转换被拒绝
- standard 模式所有现有转换行为不变

### M40C：Service / API

- `create_experiment` 接受并写入 `mode` 字段
- `start_experiment` 在 direct 模式下允许 `draft → running`
- `complete_experiment` 在 direct 模式下转换到 `done` 而非 `result_review`
- direct 模式下 `complete` 缺失 evidence metadata 时不 raise
- direct 模式下 `submit_for_review` / `accept_result` 调用被拒绝并返回有意义的错误

### M40D：CLI

- `map experiment create --mode direct` 创建 direct 模式实验
- `map experiment list` 显示 mode 列
- `map experiment start --executor participant` 在 direct 模式下正常工作
- `map --persona participant experiment complete` 在 direct 模式下直接完成

### M40E：Phase Owner / Todos

- direct 模式 running 阶段 `phase_owner = participant`
- direct 模式 running 实验出现在 participant 的 todos 中
- direct 模式 running 实验对 host 标记为 `informational_only`
