## 变更摘要

| 领域 | 现状 | v0.12 目标 |
|------|------|-----------|
| 机器可读输出 | `--format json` 只能放在子命令前；实验短 id 不被解析 | 子命令级 `--format`；`--id` 支持 8 位短 id 前缀解析 |
| 错误反馈 | 422 原样透传 pydantic envelope，无可执行提示 | 错误信封附 recovery hint 与最小正确示例 |
| 命令路由 | `topic` 命令族 4/10 已支持 uuid/fs uuid5/slug 三形态 | 除有意仅 DB 的 `migrate` 外全部统一 |

## 背景与动机

v0.11 交付了 FS 事实源、话题路由、Skill 分发与 A2A 投影，平台核心能力齐备。
但 M50–M53 两个迭代周期内，**同一个 agent（host persona）在真实使用中反复被 CLI 人机工程问题卡住**，
每次卡点都发生在「平台能力已存在、只是 agent 够不着」的缝隙上。

### 证据清单（全部来自 M51/M53 实战记录）

| # | 卡点 | 实际表现 | 代价 |
|---|------|----------|------|
| E1 | 机器可读输出缺口 | `map experiment list --format json` 报 `No such option '--format'`；全局 `--format` 必须放在子命令**之前**，与直觉相反 | 取实验完整 UUID 时被迫**直查 SQLite** `data/map.db` |
| E2 | 短 id 不解析 | `experiment show --id 0b76b432` 报 `'0b76b432' is not a valid UUID`（列表输出只有 8 位短 id） | 同上；短 id 是平台自己发出来的，却不被自己接受 |
| E3 | 错误信封不可执行 | 422 原样透传 `{"detail":[{"type":"missing","loc":["body","plan"],...}]}` | 需要对照 server 源码才能知道怎么改 |
| E4 | 键名陷阱 | `plan.content` 应为 `content_md`；报错只说 missing | 实验创建连返 422 三次 |
| E5 | frontmatter 校验无提示 | 缺 `title/acceptance/evidence_keys/dependencies` 时只报 missing，不给模板 | 同上 |
| E6 | 空列表语义 | `dependencies: []` 被判空，必须写 `dependencies:\n  - none` | 语义反直觉，文档未标注 |
| E7 | 路由覆盖不全 | `resolve / rollback-round / reopen / dismiss / read / mark-seen` 仍只收 DB UUID，与 `show / comment / advance-round / close` 行为不一致 | agent 需记忆两套 id 规则 |

## 设计原则

1. **平台发出的标识，平台必须能解析**（短 id、fs uuid5、slug 同理）。
2. **每个错误消息里包含修复路径**：错误信封必须给出 recovery hint 或最小正确示例。
3. **同一命令族行为一致**：`topic` 命令族除明确标注「仅 DB」的命令外，`--id` 语义完全统一。
4. 不引入新领域概念，全部是对既有能力的收口。

## M54 机器可读输出（P0）

**目标**：agent 不再需要查 SQLite 或肉眼解析表格。

1. `--format json` 下沉到子命令级（typer context 继承全局 option），`map experiment list --format json` 与 `map --format json experiment list` 等价；两处用法均过 CLI compat 测试。
2. `experiment show/list/accept-result` 的 `--id` 支持 8 位短 id 前缀解析（唯一前缀匹配，多义时报错并列出候选）。
3. JSON 输出与 SDK schema 对齐（`map_types` 直接序列化），保证字段名与 REST API 一致。

**验收**：以 host persona 仅凭 CLI 拿到实验完整 UUID 并完成 `accept-result`，全程无 SQLite / curl。

## M55 错误信封可执行化（P0）

**目标**：把「实验创建 422 三连」变成一次通过。

1. server 侧 422 响应附 `hint` 字段：缺失字段列出**最小正确 payload 示例**；键名错误（如 `content` vs `content_md`）做近邻匹配提示。
2. frontmatter 校验失败时返回完整字段清单 + 每字段一行说明 + 可直接复制的模板片段。
3. `dependencies` 支持空列表语义（`[]` = 无依赖），与 `none` 显式写法并存；文档同步。
4. CLI 捕获 422 后把 `hint` 渲染为人类可读块（含示例），不再裸透 pydantic detail。

**验收**：用**错误键名 + 空 dependencies** 的 payload 创建实验，agent 仅凭两次报错提示内信息修正成功。

## M56 命令路由统一（P1）

**目标**：`topic` 命令族 `--id` 语义单一。

| 命令 | 现状 | v0.12 |
|------|------|-------|
| show / comment / advance-round / close | 已支持三形态 | 保持 |
| resolve / rollback-round | 仅 DB UUID | 接入 `_resolve_topic_ref` |
| reopen / dismiss / read / mark-seen | 仅 DB UUID | 接入 `_resolve_topic_ref`（fs 目标按需降级为 no-op + 提示） |
| migrate | 仅 DB UUID | **有意保留**（迁移语义只对 DB 存在），help 文本标注 |

**验收**：`map topic --help` 中所有接受 `--id` 的命令（除 migrate）help 文本一致；新增路由回归测试覆盖至少一个 fs 目标命令。

## 非目标

- 不做 A2A transport / 跨组织发现（维持 v0.11「实验性只读投影」定位）。
- 不改实验状态机与评审流转规则（学习曲线问题留待 Skill 文档优化）。
- 不动 alembic / test_project 的 lint 盲区（单独的工程卫生项，不占 v0.12 里程碑）。

## 风险与开放问题

| 风险 | 缓解 |
|------|------|
| 短 id 前缀碰撞 | 唯一匹配放行；多义时报错并列出候选完整 UUID |
| `hint` 字段增加响应体积 | 仅 422 响应携带；成功路径不变 |
| `read/mark-seen` 路由到 fs 目标语义不明 | 本版本 no-op + 明确提示；是否给 fs 通知建 id 映射留待评审 |
| 全局 `--format` 与子命令级并存期行为 | 同一值两处出现以子命令级为准，compat 测试锁定 |
