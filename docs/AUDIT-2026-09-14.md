## P0 —— 先把 CI 变绿（当前是红的）

### 1. `pytest -n auto --cov` 覆盖率 combine 崩溃 → backend job 3/3 leg 失败

- **现象**：CI `backend (3.10/3.11/3.12)` 三个 leg 全部失败，退出码 3；Nightly 连续两天（09-12、09-13）失败。
  ```
  INTERNALERROR> coverage.exceptions.DataError:
  Can't combine statement coverage data with branch data
  ```
- **最早可确认**：`release: v0.16.1`（2026-09-11）起的 CI 即为此原因；更早在 08-31 是另一个问题（`.venv/bin` 未入 PATH，exit 127，T34 已修），09-04/09-08 是 `packaging` job exit 2。
- **根因**：`pyproject.toml` 配了 `[tool.coverage.run] branch = true`，但 CI 命令只写 `--cov`，没传 `--cov-branch`。
  pytest-cov 的 `set_env()` 只在 `cov_branch` 为真时才导出 `COV_CORE_BRANCH=enabled`；`COV_CORE_CONFIG`
  也仅在显式传 `--cov-config` 时才是具体文件路径。测试中被 `pytest-cov.pth` 激活的**子进程**因而以
  「无配置文件」启动 → 写出 **statement-only** 数据，与主进程的 **branch** 数据在 `combine()` 时冲突。
- **修复（已验证）**：pytest 命令加 `--cov-branch`。
  - `.github/workflows/ci.yml:115` → `pytest -n auto --cov --cov-branch --cov-report=term`
  - `.github/workflows/nightly.yml:45` → 同样补 `--cov-branch`（保留 `--cov-report=xml`）
  - 等价替代：`--cov-config=pyproject.toml`（让子进程也能读到 `branch = true`）。
- **复现与验证（本机）**：
  ```
  pytest -n auto --cov --cov-report= tests/test_release_script.py tests/test_systemd_install.py \
         tests/test_agent_client.py tests/test_dual_root_isolation.py
  # → INTERNALERROR（16s 复现）
  # 加 --cov-branch 后 → 46 passed，正常输出覆盖率表
  ```

### 2. 真失败用例（与覆盖率无关）：`tests/test_direct_executor_e2e.py::test_direct_complete_emits_topic_close_pending`

- 全量 `-n auto` 下失败（本机 2 次 + CI 3.10 leg 1 次，**CI 里那 1 failed 就是它**）；
